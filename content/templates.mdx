title: "Templates"
description: "Edit the templates that control the layout of your homepage, domain pages, category pages, the categories index, and the blog index in Domainer Engine."
---

**Templates** in the admin nav gives you layout control over the five main page types in the platform. Each template has its own settings — drag blocks to reorder, enable or disable modules, and customize headings.

Templates are different from [CMS Pages](/content/pages). A CMS page is a one-off page you create and manage individually. A template is a shared layout that applies to every page of that type — every domain page follows the Domain template, every category page follows the Category template, and so on.

---

## Home

**Templates → Home**

The homepage is built entirely from blocks. There is no fixed layout — add any combination of blocks and arrange them in any order.

| Field | Description |
|---|---|
| **Sections** | Block list. Start with a Hero block, then add any inventory, content, or brand blocks. |
| **Page Purpose** | A textarea describing the page's goals and audience. Used by AI when generating SEO metadata. |

The [Hero block](/content/page-builder#hero-block) is only available on the homepage and CMS pages. It is not available on other templates.

## Domain

**Templates → Domain**

Controls the **Default** layout used by every domain detail page (`/domains/{name}`) that doesn't have its own [Landing Page](/domains/landing-pages) assigned. Individual domains can opt into an alternate column ratio or block arrangement via **Domains → Landings** without affecting this template. The domain page has four distinct zones — everything in them, including the price panel and the domain name itself, is a placeable, reorderable block:

| Zone | Description |
|---|---|
| **Above** | Full-width blocks rendered before the domain header. Place the **Domain Hero** module here for the sticky scroll effect on domain names. |
| **Left Column** | The main content column. Domain modules (Curator's Insight, Use Cases, etc.) go here. |
| **Right Column** | The sidebar. Sticky by default — see Deal Section Spacing below for the one case where it isn't. |
| **Below** | Full-width blocks rendered after the main content area. |

### Layout settings

One field controls spacing independent of any block:

| Field | Purpose |
|---|---|
| **Deal Section Spacing** | Controls the top and bottom padding of the two-column content area (None / XS / S / M / L / XL). |

### Domain modules

The following modules are specific to domain pages and can be placed in the Left Column, Right Column, Above, or Below zones — nothing is shown unless you place it, including the domain name and description:

| Module | Shows |
|---|---|
| **Domain Hero** | Large sticky domain name header. Best placed in the Above zone. |
| **Domain Headline** | The domain name, an optional suffix (default "is for sale!"), and an optional category badge on the same line. |
| **Category Badges** | Standalone category badge(s) — primary category only, or primary plus every additional category. Colored (tinted by the category's own color) or neutral. Independent of Domain Headline — use one, the other, or both. |
| **Domain Description** | The domain's description and tags. Optional bordered-card treatment (matching the Perfect Match For / Use Cases look) via **Card Style**. |
| **Curator's Insight** | The curator quote from the domain record. |
| **Use Cases** | Numbered list of use cases. |
| **Perfect Match For** | Ideal buyer persona paragraph. |
| **Technical Dossier** | RDAP data: registrar, dates, name servers, transfer type. Has a **Hide young dates** option to suppress dates for recently registered domains. |
| **Branding Playground** | Brand color preview widget. |
| **Similar Domains** | Grid of up to 4 related domains from the domain's Similar Domains field. |
| **Domain Views** | A stat-tile strip of real visitor traffic (views / unique visitors, today and last 30 days) — each stat independently toggleable. |
| **Domain Views (Line)** | The same traffic stats as a single sentence with a leading icon, instead of stat tiles — the number placeholders can be bolded or colored right in the text editor. |
| **Breadcrumbs** | A standalone breadcrumb trail, for layouts whose header doesn't already show one inline. Search-engine breadcrumb data is emitted regardless of whether this module is placed. |
| **Split Row** | Two side-by-side columns, each holding any number of blocks (any module, sidebar widget, or general block — stacked if you add more than one per side). **Ratio** sets the column widths (Equal / Narrow-Wide / Wide-Narrow). **Sticky Right Column** pins the right side while scrolling (hidden when the ratio is Equal, where sticking it would run it off the bottom of the screen). **Align Shorter Column To Center** vertically centers whichever side has less content instead of top-aligning it. |

### Sidebar widgets

These widgets are available in all zones. They are most useful in the Right Column:

| Widget | Shows |
|---|---|
| **Price + Buy Now** | The price/offer panel — heading and subtext are editable right on the block. This is what shows the Buy Now button, Spaceship Checkout, and AtomPay when eligible (see [Payment Settings](/configuration/payment-settings)). |
| **Make an Offer Form** | Offer submission form. Rendered only when the domain's sale model allows offers. |
| **Inquiry Form** | Contact/inquiry form. |
| **Track Price Form** | Price drop alert subscription form. Only visible when Brevo is enabled in Notification Settings. |
| **Marketplace Buttons** | Links to Afternic, Sedo, Atom, and custom marketplaces enabled on the domain — prominence of this panel relative to Buy Now is configurable. |
| **Contact Messengers** | Direct WhatsApp / Telegram buttons, configured in [Messenger Settings](/configuration/messenger-settings). Hidden automatically if no channel is enabled, or if the domain's own **Hide Contact Messengers** checkbox is on. |
| **Transfer Info** | A short transfer process explainer. |

<Note>
  When a domain has no price set, the inquiry heading automatically changes to "Request Price."
</Note>

### General blocks

All standard [Page Builder blocks](/content/page-builder) can also be added to domain pages — CTA, Text, Features, FAQ, Video, Form, and others. These are prefixed with `·` in the block picker to distinguish them from domain-specific modules.

## Category

**Templates → Category**

Controls the layout around the domain grid on every category page (`/categories/{slug}`). Has two zones:

| Zone | Description |
|---|---|
| **Above** | Blocks rendered above the domain grid. |
| **Below** | Blocks rendered below the domain grid. |

Category-specific modules available in both zones:

| Module | Shows |
|---|---|
| **Curator Insight** | The category curator insight text from the category record. |
| **SEO Text** | The SEO text block from the category record. Has max-width (narrow/normal/wide) and Use Background options. |

All general page builder blocks are also available.

---

## Categories

**Templates → Categories**

Controls extra blocks on the `/categories` index page (the grid listing all categories). Has two zones:

| Zone | Description |
|---|---|
| **Above** | Blocks rendered above the category grid. |
| **Below** | Blocks rendered below the category grid. |

Only general page builder blocks are available here — no category-specific modules.

**Page Purpose** — textarea for AI SEO generation context.

---

## Blog

**Templates → Blog**

Controls extra blocks on the `/blog` index page. Has two zones:

| Zone | Description |
|---|---|
| **Above** | Blocks rendered below the hero carousel and above the posts heading. |
| **Below** | Blocks rendered below the post list. |

Blog-specific module available in both zones:

| Module | Fields |
|---|---|
| **About This Blog** | Title and a textarea for a short description of the blog. |

All general page builder blocks are also available.

**Page Purpose** — textarea for AI SEO generation context.

---

## How changes take effect

Template changes apply to all pages of that type immediately after saving. There is no per-domain or per-category override — the template is global (except for a domain's own [Landing Page](/domains/landing-pages) assignment). Changes are cached and propagated to the public site automatically.

Every template also has a [Live Preview](/content/live-preview) panel, so you can see how a change looks against a real page before you save.
